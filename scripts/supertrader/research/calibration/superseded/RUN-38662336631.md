# Pipeline run 38662336631 (first parallel pipeline; calibration reviews failed on a reviewer defect)

Freeze `V3-9a4f417e08f91f60` was committed before any measurement (file `BACKTEST-CALIBRATION-FREEZE-V3-38662336631.json`).
All four calibration jobs re-captured the data and proved content equality against that freeze (the jobs would have stopped on
`CONTENT_BINDING_MISMATCH`), then measured their method. The mechanical completion reported `CALIBRATION_INCOMPLETE`:
every completed screen carried a failed numeric-review hard check, so the tournament was (correctly) not started.

Cause (reproduced offline with a synthetic book that has a data-quarantine terminal): the independent numeric review counted a
data-quarantine liquidation as a missing-bar violation of `R4`. A quarantined security has no source bar on its terminal date;
the engine liquidates at the frozen last close times the scenario factor. This is a defect of the reviewer, not of the
construction. The review now checks those fills explicitly (`R4c`, price = frozen last close x scenario factor x (1 - slippage))
and still fails a fill priced differently (test). Review checks were not weakened.

Because the reviewer code is part of the freeze closure, a new run builds a new freeze; the results of this run are superseded, not
reused. The public per-method summaries of this run are retained as artifacts of the run only.
